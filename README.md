# 🌿 GreenBuddy — AI Outdoor Quest Generator

**Touch Grass with AI! 🌱**

GreenBuddy is a browser-based AI application that encourages people to spend more time outdoors through personalized, fun, and achievable outdoor quests. Users can select their available time, current mood, and location type to receive outdoor activity suggestions designed around their preferences.

The project combines artificial intelligence, web development, and wellness-focused gamification to help make outdoor experiences more enjoyable and accessible.

## 🌱 About the Project

In today's digital world, people often spend a significant amount of time on their devices and may find it difficult to make time for outdoor activities.

GreenBuddy aims to make stepping outside easier by transforming it into a small adventure.

Instead of simply telling users to go outside, GreenBuddy provides personalized outdoor quests based on their available time, mood, and surroundings.

Whether someone has five minutes for a short walk or thirty minutes to explore a nearby park, GreenBuddy can help them find an activity to try.

**Our vision:** Make spending time outdoors simple, enjoyable, and accessible to everyone.

## 🎯 Problem Statement

Many people want to spend more time outdoors but face challenges such as:

* Not knowing what outdoor activity to try.
* Having limited time during the day.
* Feeling unmotivated or unsure where to begin.
* Finding generic activity suggestions uninteresting.
* Wanting a simple way to track their outdoor experiences.

Traditional reminders to spend less time on screens do not always provide a practical next step.

GreenBuddy addresses this problem by turning the intention to go outside into a personalized, actionable quest.

## 💡 Our Solution

GreenBuddy uses an AI-powered quest-generation experience to suggest outdoor activities based on user preferences.

The user selects their available time, mood, and location type. The application then attempts to generate a suitable quest using an open-weight language model that runs in the browser.

Users can try a quest and save completed activities in a personal journal stored in their browser.

This creates a simple cycle:

**Choose your mood → Generate a quest → Step outside → Complete the activity → Record your experience.**

## ✨ Key Features

### 1. 🤖 AI-Powered Quest Generation

GreenBuddy uses an AI model to generate outdoor activity suggestions based on user input.

The goal is to provide relevant, creative, and actionable quests instead of generic recommendations.

### 2. ⏱️ Flexible Time Options

Users can choose an activity based on how much time they have available.

For example:

* 5 minutes — Notice five different things in your surroundings.
* 15 minutes — Take a mindful walk and observe nature.
* 30 minutes — Explore a nearby park or outdoor area.

These are illustrative examples, not guaranteed model outputs.

### 3. 😊 Mood-Based Personalization

Users can select their current mood to influence the type of quest suggested.

For example:

* **Relaxed:** Try a peaceful nature observation activity.
* **Bored:** Discover something interesting nearby.
* **Low on energy:** Choose a gentle, low-effort outdoor activity.
* **Adventurous:** Try exploring a new public area safely.

The suggestions are intended to be flexible and supportive rather than demanding.

### 4. 🌳 Location-Based Preferences

Users can indicate the kind of environment available to them, such as a park, garden, or neighbourhood.

This helps tailor activity suggestions to the user's surroundings without requiring precise GPS coordinates.

### 5. 📔 Personal Quest Journal

GreenBuddy includes a simple journal that allows users to record completed quests.

The journal uses browser `localStorage`, so saved entries can remain available when the same browser and website storage are used again.

### 6. 🔄 Fallback Quest Suggestions

If AI generation fails or the model is unavailable, the application can display predefined sample quests.

This helps demonstrate the core experience even when the AI service cannot generate a response.

Fallback suggestions should not be confused with responses generated by the AI model.

### 7. 💻 Browser-Based Experience

The application is built with HTML, CSS, and JavaScript and runs in a web browser.

The AI model is loaded using Transformers.js, allowing supported models to run locally in the browser after the required model files have been downloaded.

## ⚙️ How It Works

The GreenBuddy workflow consists of the following steps:

1. **User input:** The user selects their available time, mood, and location type.
2. **Prompt creation:** JavaScript combines the selected preferences into a prompt for the AI model.
3. **AI processing:** The application attempts to generate an outdoor quest using the loaded model.
4. **Result display:** The generated suggestion is displayed on the webpage.
5. **Quest completion:** The user can try the suggested activity.
6. **Journal entry:** Completed quests can be saved in the browser's local storage.

If model loading or generation fails, the application can use its fallback quest suggestions.

## 🚀 Getting Started

Follow these steps to run GreenBuddy on your computer.

### Prerequisites

You will need:

* A computer with a modern web browser.
* An internet connection for the initial download of the required AI model and JavaScript library.
* A code editor such as Visual Studio Code.
* Basic knowledge of HTML, CSS, and JavaScript is helpful but not required.

### Step 1: Clone the Repository

After uploading the project to GitHub, open a terminal and run:

```bash
git clone https://github.com/YOUR-USERNAME/GreenBuddy.git
```

Replace `YOUR-USERNAME` with your GitHub username and `GreenBuddy` with your actual repository name if it is different.

Move into the project folder:

```bash
cd GreenBuddy
```

Alternatively, download the repository as a ZIP file from GitHub and extract it.

### Step 2: Open the Project

Open the project folder in Visual Studio Code.

Make sure these files are present:

```text
index.html
style.css
app.js
```

### Step 3: Run the Application

For a simple local setup:

1. Open the project folder in Visual Studio Code.
2. Install the **Live Server** extension if you do not already have it.
3. Right-click `index.html`.
4. Select **Open with Live Server**.
5. Your browser should open the GreenBuddy webpage.

Using a local development server is recommended for a smoother browser-based development experience.

### Step 4: Load the AI Model

When you request your first quest, the application attempts to load the configured model through Transformers.js.

The initial model download may take time depending on your internet connection and the size of the model.

Keep the browser tab open while the model loads.

If the AI model cannot load, check your browser's developer console for errors and verify that you have an internet connection.

### Step 5: Test the Application

Try different combinations of:

* Available time.
* Mood.
* Location type.

Generate quests and check that the result is displayed correctly. Then test whether completed activities can be added to the journal.

## 🧠 AI Model and Implementation

GreenBuddy uses Transformers.js to load and run a compatible model in the browser.

The starter implementation is configured to use:

`Xenova/LaMini-Flan-T5-248M`

The model is accessed through the Transformers.js pipeline API. The application creates a text prompt using the selected preferences and asks the model to produce an outdoor quest.

### What Does Open-Weight AI Mean?

Open-weight models make their trained model weights available for people to download and use under the applicable model licence.

They can enable developers to experiment with AI without necessarily relying on a paid, hosted AI API.

However, open weights do not automatically mean that every part of a project is open source, unrestricted, or completely offline. Always check the model's licence and the licences of the libraries used.

### Does GreenBuddy Work Offline?

The application is designed to run the AI model in the browser, rather than requiring a remote AI inference API for every generation.

However, the first model download requires internet access. Running the model offline afterward depends on whether the required model files and application resources are available locally and whether browser caching and the serving setup support offline use.

**Offline operation should be tested rather than assumed.**

### AI Limitations

AI-generated quests may occasionally be repetitive, unclear, or unsuitable for the user's environment. The application should display understandable suggestions and provide a fallback when generation fails.

Users should review suggestions before following them, particularly when an activity involves unfamiliar locations or environmental conditions.

## 🔐 Privacy

GreenBuddy's starter implementation stores journal entries in browser `localStorage`.

This means the journal is stored within the browser's local website storage rather than automatically being saved to a GreenBuddy account.

Important considerations:

* Journal entries may be lost if browser storage is cleared.
* Entries are not automatically synchronised between devices.
* Other people using the same browser profile may be able to access saved entries.
* The application does not need precise GPS coordinates to use its location-type preference.
* The AI model and library may be downloaded from external hosting services during setup or first use.

Review the actual application code and network requests before making broader privacy or security claims.

## ⚠️ Limitations

GreenBuddy is an early-stage project and has several limitations:

* AI-generated suggestions may not always follow the requested format.
* Model loading and generation speed depend on the device, browser, and available resources.
* The initial model download requires internet access.
* AI generation can fail because of network, compatibility, or resource issues.
* Fallback suggestions may be less personalised than AI-generated quests.
* Journal entries are stored locally and are not synced across devices.
* The application does not automatically verify real-time weather, opening hours, or local safety conditions.

Users should choose activities that are appropriate for their surroundings and avoid unsafe or restricted locations.
